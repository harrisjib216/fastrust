## Verdict

The dashboard shows hex-simd 18x faster at encoding (4 KiB) and 23x faster at decoding (1 KiB) than the hex crate, and about 6x faster at 16 bytes. hex 0.4.3 has not had a release since 2021, so the gap to the default still stands; const-hex's separate benchmark also shows hex an order of magnitude behind SIMD hex crates.

**Why tier C:** First-party dashboard generated by CI; benchmark code is public but the CPU and toolchain are not stated.

## Use it when

- Encoding or decoding hex in bulk (hashes, binary dumps) where hex 0.4 is a hotspot
- You also want SIMD check-only validation

## Skip it when

- You want a crate with recent releases: last hex-simd release is 0.8.0 (2022-12-28)
- You prefer a drop-in API for hex: const-hex mirrors hex's API

## How it is fast

Processes whole SIMD registers of input per step, with kernels chosen at runtime; decoding and validation follow the vectorized hex-parsing approach in Wojciech Muła's article cited in the README.

## What it costs

- The README says the project relies heavily on unsafe code

## Problems with the evidence

- First-party numbers from 2023-04 with no hardware stated
- hex/fallback decode at 4096 bytes (0.293 GiB/s) is lower than at 1024 bytes, which suggests noise in that cell
- faster-hex in this dashboard is pre-1.0; faster-hex 1.0 (2026-09) was rewritten
